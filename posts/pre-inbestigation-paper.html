    only encoder

    • the different kinds of encoders and dncoders defend on the different kind of tasks model need solve.
    • Bidirectional input processing
    • Strong understanding capabilities
    • Not well-suited for direct long-text generation

    only decoder

    • Can only process left-side input
    • Inherently suited for generation
    • Can perform many tasks, but primarily relies on prompting / next-token prediction

    encoder-decoder

    • Encoder handles input comprehension
    • Decoder handles output generation
    • Combines understanding and generation capabilities

    LLaVA1.0

    Architecture

    • Vision encoder: CLIP-pretrained ViT-L/14

    • Projection layer: a trainable linear matrix $W$

    • Language model: Vicuna (decoder-only LLM)

    Data construction

    LLaVA 1.0 does not rely on large-scale human-written multimodal instructions.\ Instead, the authors use:

    • image captions
    • bounding boxes

    as textual visual context, and prompt GPT to generate three types of instruction-following data:

    • conversation
    • detailed description
    • complex reasoning

    Training

    Stage 1: Feature Alignment

    • freeze visual encoder

    • freeze LLM

    • train only projection matrix $W$

    align CLIP visual features to the pretrained LLM embedding space

    This stage can be viewed as:\ training a compatible visual tokenizer for the frozen LLM

    Stage 2: End-to-End Fine-tuning / Visual Instruction Tuning

    • keep visual encoder frozen

    • train $W$ + LLM

    teach the model to answer image-grounded instructions, including:

    • multimodal chat
    • detailed image description
    • complex reasoning
